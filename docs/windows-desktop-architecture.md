# 采音脚本 4.0.0：Windows 桌面录音架构

## 已确认的路线

4.0.0 采用 **Windows 独立桌面程序**，不依赖外部浏览器和手机 WebSocket 服务。桌面程序包含一个本地界面，同时承担电脑录音、局域网同步主控和同步客户端三种职责。

## 技术选择

| 层 | 方案 | 职责 |
|---|---|---|
| 桌面外壳 | Electron + TypeScript | 生成单个 Windows 安装包，提供受控的本地界面与 IPC |
| 主进程 | Node `net` | 以现有 `SCRIPT-RECORDER-SYNC/1` 换行 JSON 协议创建 TCP 房间或加入手机主控 |
| 渲染进程 | React + Web Audio API | 麦克风选择、录音设置、波形、主控/加入界面与状态显示 |
| 音频编码 | PCM 到 WAV 编码器 | 以 16-bit 或 32-bit、单声道或双声道保存电脑录音 |
| 文件输出 | Node `fs` | 将录音保存到用户选择的目录，并按统一目录和命名规则覆盖重录旧文件 |

Electron 的渲染层能够使用 Chromium 的媒体设备 API；主进程可通过权限处理器和预加载脚本将最小化的文件、网络接口暴露给界面。Node `net` 可创建 TCP 服务端和客户端，因此可直接对接现有 Android 原生 TCP 房间协议，无需增加 WebSocket 转换层。[1] [2]

## 跨端同步协议契约

电脑端将与 Android 继续使用：

```text
SCRIPT-RECORDER-SYNC/1\n
{JSON message}\n
```

房间口令、设备上线/离线、设备状态、心跳、录制控制命令、句数校验与同步完成命令保持现有含义。主控与客户端的准入规则保持为：房间口令正确、至少一台在线客户端、各设备脚本句数相同；脚本名称和句子内容不参与准入判断。

## 录音与文件契约

桌面端配置项目包括采样率、声道、位深、首端静音、尾端静音、麦克风设备和数据保存根目录。默认目录结构与手机端统一为：

```text
{保存根目录}/record_jxb/wave/{发音人名_性别_年龄岁}/{任务名}/
```

单句文件名统一为：

```text
任务名_发音人名_句子编号_时间戳.wav
```

其中句子编号固定为三位数，例如 `采样任务_张三_004_20260911-143000.wav`。当用户重录某句时，程序会先删除该句历史记录的私有文件和公共文件，再保存新的带当前时间戳文件；界面、公共目录、整包分享均引用新文件名。

## 安全边界

桌面窗口启用 `contextIsolation`，禁用直接 Node 集成。界面仅通过预加载层访问经过参数校验的录音、路径选择、文件保存和同步接口。局域网 TCP 仅处理当前协议的首行、受控 JSON 消息与限定端口，不执行外部输入的命令或路径。

## Windows 验证前提

本沙箱可完成 TypeScript 源码、协议和文件命名测试，但不能替代 Windows 麦克风驱动、系统权限和 `.exe` 包的最终验收。完成源代码后，需要在 Windows 10/11 上构建或安装桌面包，并与至少一台 Android 真机在同一局域网验证。
